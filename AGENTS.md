# Glass Root Landscape Studio — development instructions

## Current authoritative direction
- Three.js is the official target for all new 3D graphics development. The main editor's `studio-three.js` is the current Three.js scene renderer. The 2D plan remains the authoritative editing interface and project model. Classic Canvas 3D is a compatibility fallback only: fix regressions if necessary, but do not spend development time improving its visual style.
- Desired aesthetic: very realistic stylized cartoon / botanical architectural visualization, with matte materials, dense natural foliage, convincing silhouettes, tapered growth, believable depth, and realistic lighting; not glossy geometric blobs or photographic textures.
- Maintain the existing 315 regional plant records, stable plant IDs, feet-based saved geometry, GIS, ecology, mass planting, editing and proposal functionality. No paid dependencies, commercial assets, or mandatory accounts. Three.js is pinned to r180 for now; document and test any dependency change. The first load currently uses a public CDN; offline vendoring can be addressed separately.

## Botanical authority and plant model workflow
- Lady Bird Johnson Wildflower Center is the primary authority for plant information. Use BONAP/NAPA for county nativity. Regional floras and existing Grass ID Lab research can supplement visible morphology where needed; cite source links and identify conflicts or unknowns instead of inventing traits. Keep source data distinct from artistic rendering choices.
- The species-mesh-lab/ site is the independent botanical model development and review workspace. Its current raw WebGL preview is acceptable during transition; new production models must be consumable by Three.js. The lab owns experimental geometry and source notes, not the landscape editor or project schema. The main Studio owns scene assembly, camera, lighting, materials, terrain, instancing and integration.
- Shared ES modules and a registry keyed by existing palette ID and exact scientific name now exist. Studio consumes them through an opt-in prototype comparison switch; promotion to default requires visual review. Do not maintain competing copies of the same species generator. Keep the current Studio's working muhly implementation until the shared replacement passes review. Lab prototypes are not automatically approved for production.
- A species model should supply deterministic seeded variation, high/medium/low (and lightweight mass proxy when appropriate), appropriate foliage/flower/seedhead appearance states, source notes, and valid mesh position/normal/color buffers (or an explicitly documented compatible mesh asset). Normalize production instances to stored project spread and height in feet. Preserve actual botanical traits between quality levels; avoid implying exact calendar phenology from illustrative stages.
- Develop and review a few species at a time; dense foliage and distinctive shape matter more than raw polygon count. Use shared instancing, render-on-demand, geometry reuse, and eventually distance/screen-size LOD. Track triangle counts, draw calls and live browser performance. Record which species are prototypes, reviewed, and integrated; do not count generic growth-form templates as completed species models.

## Coordination and safety
- Before editing, inspect the current repository and the latest file SHA; multiple chats may be working concurrently. Avoid overlapping writes. Lab work should be confined to lab/shared plant asset files unless explicitly coordinating an integration. Main editor work should not overwrite ongoing lab files. Preserve prior source records and user-approved models.
- Do not retire classic view until live Three.js loading, camera, exports, saved-project compatibility and realistic large-planting performance are verified. Current Studio supports plant selection, placement, movement and inspector edits in the integrated viewport; other drawing modes still use 2D. Aerial imagery is composited onto Three.js terrain using the existing calibrated footprint; user confirmed the aerial workflow works. Buildings now have configurable procedural roofs and finishes in Three.js, pending browser review; hardscape remains basic. Keep these limitations explicit.
- Current priority: establish shared plant asset contract and model registry, then refine species models, performance, buildings, materials, hardscape, water/terrain and presentation. Full insect database integration (v0.9.3) stays on hold; preserve research links and existing evidence summaries.
- Update README with actual changes, tests and limitations; distinguish simulated checks from real browser tests. Do not claim deployment, visual review, or approval without evidence.
